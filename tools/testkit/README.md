# QL printer test kit

Help test a free Windows driver for Brother QL label printers ("QL Unidrv driver", ARM64 and x64). The driver
supports 18 models, but its authors only own a QL-570 and a QL-800. For every other model the driver's output is
checked against recordings of Brother's own driver, never on a real printer. If you own one of these printers,
this kit prints a few test labels with exactly the data our driver would send, and writes a short report.

The kit has test labels for **every Brother roll of the model**: one label at the default length or size per
roll, plus a few extra tests (cut every 2, 300 × 600 dpi, mirror, compressed) on the 62 mm continuous roll.

## What it does, and what it doesn't

- It talks to the printer directly over USB (as Brother's status monitor does): it reads the printer's status
  (model, loaded roll, errors) and sends the test labels.
- **Nothing is installed or changed** on your PC, no administrator rights are needed, and your Brother driver
  stays as it is. Only `qltest-report-....txt` is written into the kit folder.
- With QL Unidrv's status service installed (*Printer status service for shared printers*), the script pauses it
  for the test and says so; it resumes at the end, or by itself after 10 minutes.
- Each label costs a few centimetres of tape (one 102 × 152 mm label on the wide models).

## How to run it

1. The printer is connected by **USB**, switched on, with a roll loaded. Nothing else is printing on it.
   (QL-700, QL-800 series: the "Editor Lite" LED must be off; a printer that shows up as a USB drive is in
   its Editor Lite / mass storage mode.)
2. Unzip the kit (if Windows blocks scripts from downloads: right-click the zip → *Properties* → *Unblock*
   before unzipping).
3. Open PowerShell in the kit folder (in Explorer: *File* → *Open Windows PowerShell*, or Shift + right-click)
   and run:

   ```
   powershell -ExecutionPolicy Bypass -File .\qltest.ps1
   ```

4. The script shows the printer's model and roll, then the test labels for that roll. Each test shows a picture
   of what the label should look like in a small window of its own; `Enter` prints it, `s` skips it, `q` stops.
   After each label it asks whether the label looks like the picture (`y` / `n`: border, text, bars; cut where
   expected).
5. Send back the report file `qltest-report-<model>-<time>.txt` (and a photo if something looked wrong):
   - as a GitHub issue: <https://github.com/joffs/ql-unidrv/issues/new?template=printer-test-report.yml>
     ("Printer test report"; drag the file in), or
   - by e-mail to **ql-unidrv@joffs.de** if you don't have a GitHub account.

   Good results are just as useful as bad ones. Want to be named on the thanks page? Say so in the form or in your
   mail (the report itself carries no names).

Only the printer status, without printing: `powershell -ExecutionPolicy Bypass -File .\qltest.ps1 -StatusOnly`.
Every technical line on the screen too (dimmed; the report always has them): `powershell -ExecutionPolicy Bypass -File .\qltest.ps1 -Details`.

## Network models (QL-580N, 710W, 720NW, 810W, 820NWB, 1060N, 1110NWB, 1115NWB)

If your printer is also on your network (Ethernet or Wi-Fi), a second, short test helps: the driver's printer
status for network printers reads the same value Brother's own software reads (SNMP); so far only a QL-720NW has
answered it.

```
powershell -ExecutionPolicy Bypass -File .\qltest.ps1 -Network 192.0.2.50 -Watch 60
```

(your printer's IP address, from its network settings page or its printed configuration; or the name of a
Windows printer that prints to it over the network). The script

- reads the printer's status over the network (nothing is sent to its print port, so other PCs' jobs are safe);
- with `-Watch 60`, records every change for 60 seconds: meanwhile open and close the roll cover, take the roll
  out and put it back, print something from any PC;
- then offers to print one 62 mm test label over the network (needs the 62 mm continuous roll, e.g. DK-22205, US: DK-2205; `-StatusOnly`
  skips it).

It writes `qltest-report-<model>-network-<time>.txt`; send it like the USB report. If the printer is on USB at the
same time, the USB test's report helps to compare both answers. SNMP must be enabled on the printer (it is by
default); if its community isn't `public`, add `-Community <name>`.

If the printer's red light blinks after a label (an error, e.g. the wrong roll): open and close the roll cover,
or switch the printer off and on. The script waits for you.

## What the report contains

The kit's build date, the Windows version, the printer's 32-byte status messages (model code, roll, errors), the
USB product ID and port, the name of the driver on that port, and your answers. No personal data: not the printer's
serial number (part of its USB device path), not the names you gave your printers, no IP address, computer name or
folder - the screen may show them, the report doesn't.

## For the maintainers: building and using the kit

### How to handle the files

| Where | What it is | What to do with it |
|---|---|---|
| `tools\testkit\` (in git) | the sources: `qltest.ps1`, `make-testkit.ps1`, this README | edit here; contains **no** test labels |
| `reference\captures\testkit\` (in git) | Brother's output of the kit's pages with the neutral text "QL test" (all 18 models) | the source of the kit's labels |
| `out\testkit\kit\` (not in git) | the built kit: script, README, `streams\<model>\` (labels `.prn`, expected pictures `.png`, `cases.tsv`) | run it yourself from here |
| `out\testkit\ql-testkit-<model>-<date>.zip` | the kit for one model | send this to an owner of that model |
| `out\testkit\ql-testkit-all-<date>.zip` | the kit for all 18 models | for a download page, or a tester with several models |
| `out\testkit\reports\` | reports of runs started from `tools\testkit` | read them; testers send theirs back by mail/issue |
| `out\testkit\HOW-TO.txt` | these steps in short | – |

1. **Build** (after `build.cmd`, or after changing the encoder): `tools\testkit\make-testkit.ps1`. It rebuilds
   `out\testkit\` from scratch (old zips are deleted) and stops if the encoder no longer reproduces Brother's
   captures.
2. **Try it yourself** on a printer you own: load a 62 mm roll, then
   `powershell -ExecutionPolicy Bypass -File out\testkit\kit\qltest.ps1`. Running `tools\testkit\qltest.ps1`
   works too: it then takes the labels from `out\testkit\kit` and writes the report to `out\testkit\reports`.
   With several printers connected it lists each one with port, Windows printer name, model and roll.
3. **Send** the zip for the tester's model (with the driver release or by mail); they unzip it and follow
   "How to run it" above. Their report lands next to `qltest.ps1` in their unzipped folder.
4. **Record** each returned report: status codes in `docs/models.md` §3, the result in §4 and in
   `docs/differences-from-brother.md`; keep the report in `out\testkit\reports` (or attach it to the issue).
   A label marked PROBLEM: compare with Brother's capture of the same case (`reference/captures/<model>/`).

### Details

- `tools\testkit\make-testkit.ps1` (no admin) builds `out\testkit\kit\` and the zips
  `out\testkit\ql-testkit-all-<date>.zip` and `ql-testkit-<model>-<date>.zip`. It needs `replay_test.exe` from
  `driver\build.cmd` (or `-ReplayTest <path>`).
- The streams are our encoder's output, not copies of Brother's: `replay_test <captures> <model> <dir> usb`
  decodes each page in `reference\captures\testkit\<model>\` and re-encodes it as our driver does on a USB port
  (and, for the QL-580N, QL-710W/720NW, QL-810W/820NWB, QL-1050/1060N and QL-1100 series, also the compressed network form). The pictures are
  those pages' previews, turned into the printed view (mirrored back; 300 × 600 halved in height).
- What a report answers: the status codes (`docs/models.md` §3 is from Brother's files for most models), whether
  our USB form prints (the gap listed in `docs/differences-from-brother.md`), the QL-700's density byte, 12 mm
  round margins, black/red on the QL-810W/820NWB. Record results in `docs/differences-from-brother.md` and
  `docs/models.md` §4.
- `qltest.ps1 -Print <file.prn> [-Force]` sends any stream (checks the roll first unless `-Force`); `-List`
  lists connected QL printers (port, Windows printer name, model, roll); `-Device <text>` picks one of several by
  port (`USB001`), printer name or device path.
